Your files. Your models.

CODEZY is a permissioned bridge between a language model and one folder on your disk. This page covers the short version: install it, pick a tool-capable model, link a folder, and fix the errors that actually happen.

01

Start here

One installer, one model, one folder. You can make a real edit in about ten minutes.

Recommended

Windows installer

Run CODEZY-Setup-3.1.6.exe. The build is unsigned, so SmartScreen may ask for More info → Run anyway. Your data survives upgrades.

Terminal or source

CLI and development

npm i codezy-cli for the terminal (add -g to put codezy on your PATH). From a checkout: npm install, then npm run dev. The CLI needs Node 18+.

Four steps

Install, then launch.

Ollama should be running at http://127.0.0.1:11434. A 7B Q4 model wants roughly 8 GB of free RAM.

Pull a tool-capable model.
ollama pull qwen2.5-coder:7b
ollama list

This is the default recommendation. Chat works without tools; agent mode does not.

Link the project folder.

Use the folder button in the composer. That folder is both the context and the security boundary.

Ask for one concrete edit.

“Read index.html and change the h1 to ‘Hello from CODEZY’. Make the edit now.” Accept the edit card or approval, then open the preview.

Five-minute smoke test

List the files you can see, then quote the first heading of index.html.
Change that heading to "Hello from CODEZY".
Search the web for the latest Ollama release and cite the URL.

If the first line fails, the model is not receiving the folder or is too weak to follow the setup card. Start a new chat and read E10; do not argue with a poisoned transcript.

What the first send actually does

  • Checks Ollama, then asks /api/show what the selected model can do.
  • Builds a system prompt with a setup card (folder, edit mode, web mode, model limits) and the folder tree. Classic mode also receives the real file contents of text files.
  • Repeats the setup facts as a synthetic turn immediately before your question. Small models weight the newest turn most heavily.
  • Uses agent mode only when the chat has a folder, agent mode is on, and the model reports tool support.
Upgrading from an older build Agent mode used to be a buried opt-in. 3.1.5 turns it on once for existing settings via the agentModeMigrated marker. Check Settings → Agent → Reply & agent mode; turn it off there if you deliberately want the old behavior.
02

Models that work

A model can be brilliant at code and still be unable to run agent mode. Tool calling is the gate — not size, not benchmark rank.

The picker badges installed models from Ollama’s capabilities. tools means agent mode can read, search and write; chat only means edits use classic blocks. The table is a starting point; the runtime probe is the final word.

ModelAgentRAM (Q4)Best at
qwen2.5-coder:7b defaulttools~8 GBEveryday agent work. Best quality per GB; start here.
qwen2.5-coder:14btools~12 GBSharper multi-file edits; slow if it spills to CPU.
qwen2.5-coder:32btools~24 GBBest local quality. Needs a large GPU or a lot of RAM.
qwen3:8btools~8 GBReasoning and tools; thinking mode feels slower.
llama3.1:8btools~8 GBReliable general chat and tools; less code-specialised.
codellama:13bchat only~10 GBCompletion and classic edits. No tool calling.
llama2-uncensored:7bchat only~6 GBChat only; not a coding default.

Check a model yourself the runtime probe

ollama show qwen2.5-coder:7b   # capabilities: completion, tools, insert
ollama show codellama:13b      # completion only — no tools

# the exact call CODEZY makes (PowerShell)
Invoke-RestMethod http://127.0.0.1:11434/api/show `
  -Method Post -ContentType 'application/json' `
  -Body '{"model":"qwen2.5-coder:7b"}' | ConvertTo-Json -Depth 4

If tools is absent, agent mode cannot run on that model. Classic edit blocks still work.

The 400 you should not debug 
Ollama error 400: {"error":"registry.ollama.ai/library/codellama:13b does not support tools"}
The model never supported the tools schema. 3.1.5 detects that before sending, states it in the setup card, and uses classic mode with your real files instead of letting the engine throw. See E09.

Choosing by machine

Your machinePickWhy
8 GB RAM, integrated GPUqwen2.5-coder:7bFits with Windows open; expect token-by-token speed.
16 GB RAM, 8 GB VRAM:7b, try :14bThe 14B is better but may spill. Measure with ollama ps.
32 GB+ RAM, 24 GB VRAM:32bBest local coding quality; still slower than a hosted model.
No tools neededcodellama:13bClassic mode includes the real files, so a completion model can still edit.

RAM math is not file size: a 7B Q4 file is ~4.5 GB, but loading it needs KV cache and overhead. ollama ps shows the real GPU/CPU split. The composer changes the model for this chat; Settings → Models → Providers & endpoint changes the default for new chats. A cloud picker badge is a hint, not a promise — a 400 triggers the same classic fallback.

03

Chat, files and agent mode

Two ways to change the same folder: classic edit blocks, or the agent tool loop. Both stay inside the linked folder.

 Classic chatAgent mode
Turned on byNo folder, v2 off, or a model without toolsFolder + v2 + tools
What it seesTree + real text-file contents + setup cardTree; reads files itself with read_file
How it edits===FILE / ===SEARCH / ===REPLACEwrite_file, edit_file
How it searchesThe app attaches results before the turnThe model calls web_search / web_fetch
ApprovalOne accept-edits card per replyPer-action dialog for write / edit / run
Best forQuestions, small edits, non-tool modelsMulti-file work, exploration, tests, long tasks

Resolution order: v2 on → a linked folder exists → the provider is Ollama (probe) or cloud (assumed) → /api/show reports tools. Only then is the tools schema attached. A “does not support tools” 400 triggers one classic retry with a readable notice.

Linking a folder

  • The tree is always injected; hidden folders, node_modules, .git and build output are skipped.
  • Classic mode also injects text files root-first, up to ~14,000 characters. Files over 64 KB, binaries and NUL-containing files are skipped.
  • The classic injector skips secret-looking files (.env, .npmrc, private keys, .pem, .p12). Agent tools can read what you link, so link a project — not your home folder.
  • Clearing the link does not delete anything. Two chats can point at different projects.

The edit-block language classic mode

===FILE: index.html
===SEARCH
<h1>My cats</h1>
===REPLACE
<h1>Hello from CODEZY</h1>
===END
  • Existing file: the SEARCH text must match exactly once, indentation included. Small hunks beat full rewrites.
  • New file: SEARCH is the single word EMPTY; REPLACE is the complete file.
  • No header, no write. A block without ===FILE: is ignored. Leading code fences are tolerated.
ActionResult
AcceptWrites the selected hunks after backing up the previous version. Undo is offered in the toast.
AlwaysApplies and stops asking for this file in the session.
DeclineLeaves disk untouched; the proposal stays in the transcript.
/undo · /historyReverts the last batch, or restores any safety copy.

plan forbids edits. build asks before each apply. auto applies immediately and backs up. Path confinement and destructive-command rejection still apply in auto.

  • Approvals: build mode pauses before write_file, edit_file and run_command. Reads and state tools do not prompt.
  • Auto: the desktop still writes backups and keeps /undo. The CLI’s --auto does neither — run it on a branch.
  • Path guard: every model-supplied path is resolved against the linked roots. Outside means refused before any I/O: path outside the linked folders: C:\Users\you\secrets.txt. See E18.
  • Destructive commands are rejected before approval. Hung model waits and commands have wall-clock caps.
  • Desktop backups live under ~/.codezy/backups/<session>. The CLI relies on Git or your own copy.

Web search

Web chipClassic chatAgent
auto (default)Searches when the question needs current facts and attaches evidence.Unchanged: tools are always available.
alwaysSearches every turn, even for local questions.Unchanged.
offNo pre-search; the setup card says the web is off.Unchanged — the chip is a classic-chat setting.

Search tries DuckDuckGo HTML, then its Instant Answer API, then Wikipedia. A 202 challenge or 429 is upstream, not a missing key; retry, switch network, or paste a URL and use web_fetch. Results are plain text evidence — no headless browser, no persisted pages. A small classic model can still ignore the evidence and claim it cannot browse: that is E11, not a search bug.

Live preview

  • codezy-preview://<sessionId>/<path> serves the linked folder directly. Relative CSS, JS and images resolve.
  • Opens index.html at the root, or the first HTML file in a shallow scan (depth 3, 40 files).
  • A file watcher reloads the pane after the agent writes. Viewport presets: fit, desktop, tablet, phone.
  • It is not a dev server: no HMR, no Node runtime, no SSR. Vite/Next apps need their own server. Traversal outside the roots is blocked by the same path guard. See E29.
04

Terminal

The same settings, sessions and harness without Electron. Best for long multi-file jobs, scripting and CI.

npm i codezy-cli                 # add -g to put codezy on your PATH
npm i -g .                       # or: from a checkout of the CLI repo

codezy                           # interactive chat TUI
codezy "explain this error"      # one-shot, then exit
codezy exec "fix the tests" --auto
codezy --agent --dir ../my-repo  # agent REPL over a folder
codezy doctor                    # install / settings / endpoint / model / git
FlagMeaning
-p, --print <prompt>One-shot; omit the value to read stdin.
-a, --agentUse the tool-calling agent (tools + approvals).
--model <id>Override the settings model for this run.
--dir <path>Workspace root. Agent mode needs one.
--autoApprove gated tools automatically for this run.
-c, --continueResume the last saved agent session.
--output-format <fmt>One-shot output: text, json or stream-json.

The agent REPL

CommandDoes
/root [dir]Show or set the workspace root.
/todosShow the current checklist.
/model [id]Show or switch the model. /model fast <id> sets the cheap model for summaries.
/thinking · /autoToggle long reasoning or automatic approvals.
/search <q>Web search without involving the model.
/compact · /resumeSummarize older context, or restore a saved session.
/tools · /mcpList agent tools, including MCP, or server status.
/usage · /exportTokens used, or save the transcript as Markdown.

codezy doctor --json is the machine-readable form. Exit codes: 0 OK, 1 runtime error, 2 usage error.

Every command documents itself: codezy --help, codezy exec --help and codezy doctor --help print command-specific text with aligned options, a short “what it does”, and exit codes. The REPL banner reports the model’s capability (tools or chat only) from /api/show; /model re-probes after a switch.

The agent REPL keeps one quiet phase line while a local model thinks: step 3: run command npm test…. It is drawn with nanospinner, adds elapsed seconds after two, drops frames while you type or answer an approval, and stays off in pipes. The loop is driven directly instead of start(), so Ctrl+C still interrupts a turn. The chat TUI has its own built-in spinner.

Automation that runs unattended codezy exec "…" --auto does not ask before writes and does not create desktop-style backups. Run it on a branch or a disposable checkout. Path confinement and destructive-command rejection still apply. See E23.

MCP servers optional

Settings → Tools → MCP servers adds a local stdio server; its tools join the agent as mcp__<server>__<tool>. Use an absolute command if npx is not on the app’s PATH. One broken server is isolated. Tools are agent-only. Third-party MCP tools are not automatically approval-gated — CODEZY gates its own writes and commands, not a server’s. Treat any server as privileged code. See E27.

Local inference stays on 127.0.0.1. Sessions, memory and backups are not uploaded; there is no telemetry endpoint. Web search sends only the query to DuckDuckGo/Wikipedia (or the URL you fetch). A cloud provider receives the prompt only when you select one. To back up, close the app and copy ~/.codezy.

Do not “fix” the app by deleting data For launch or blank-window problems, delete %APPDATA%\CODEZY\Cache and GPUCache only. Deleting ~/.codezy removes chats, memory, backups and provider keys. For a corrupt settings file, rename it to settings.bak.json and restart.

Known errors

Search by symptom or exact engine text. Every entry is collapsed until you open it; each has a cause and a fix.

37 / 37 errors

Press / anywhere to focus the search; Esc clears it. Opening a result reveals the cause and fix.

E01CODEZY won’t start — “Unable to move the cache”Launch
Unable to move the cache: Access is denied. (0x5)
Cause
Another CODEZY/Electron process still owns Chromium’s cache — often a stale electron.exe after a crash or a second window.
Fix
Quit every CODEZY window, end any CODEZY/electron process in Task Manager, delete %APPDATA%\CODEZY\Cache and GPUCache, then relaunch. Your chats live in ~/.codezy — do not delete that.
E02Window opens blank after an updateLaunch
(no error — black/white window, no UI)
Cause
A stale GPU cache, a half-written renderer bundle, or a GPU driver rejecting the compositor.
Fix
Reset the cache as in E01. Launch once with --disable-gpu (add it to the shortcut target). Check ~/.codezy/logs/main.log. If it persists, reinstall 3.1.6 over the existing app; user data is preserved.
E03Windows SmartScreen blocks the installerInstall
Windows protected your PC
Cause
The build is not code-signed, so Windows shows the generic reputation warning.
Fix
Click More info → Run anyway. Verify the file hash/source first. Do not disable Defender or SmartScreen globally. If your organisation blocks unsigned installers, build from source or ask IT to sign it.
E04Installer finishes, but CODEZY won’t openInstall
(no window; no shortcut; nothing in Task Manager)
Cause
Antivirus quarantined the exe, the per-user install path was blocked, or a previous install is half-removed.
Fix
Look for CODEZY.exe under %LOCALAPPDATA%\Programs\CODEZY and run it directly. Check Defender’s protection history. Re-run the installer as your normal user (not elevated), then read ~/.codezy/logs/main.log.
E05codezy is not recognisedCLI
'codezy' is not recognized as an internal or external command
Cause
npm’s global bin folder is not on PATH, or the package was not installed globally.
Fix
Run npm config get prefix, add its bin directory to PATH, then open a new terminal. Or use npx -y -p codezy-cli codezy. From a checkout of the CLI repo, node index.mjs always works.
E06PowerShell refuses to run npm.ps1Install
npm.ps1 cannot be loaded because running scripts is disabled on this system
Cause
The PowerShell execution policy blocks npm’s script wrapper.
Fix
Use npm.cmd install -g codezy-cli, or allow local scripts for your user: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned. Do not set Unrestricted machine-wide. Open a new terminal afterwards.
E07Can’t reach Ollama on 127.0.0.1:11434Ollama
fetch failed · ECONNREFUSED · Ollama is offline
Cause
Ollama is not running, crashed, is bound to another host/port, or a firewall blocks the loopback call.
Fix
Start the Ollama app or run ollama serve. Verify ollama list in a terminal. If you changed OLLAMA_HOST, update Settings → Models → Providers & endpoint. CODEZY tries to start Ollama on the first chat, but it cannot if the binary is missing.
E08The model isn’t installedModels
model "…" not found · API error 404: model not found
Cause
The selected id is not in ollama list, the tag is wrong (:7b vs :latest), or a cloud provider uses a different model id.
Fix
Run ollama pull <id>, then pick it again. For a provider, copy the exact model id from its dashboard and check the base URL ends in /v1 where required. See E31.
E09The model does not support tools (HTTP 400)Models
Ollama error 400: {"error":"registry.ollama.ai/library/codellama:13b does not support tools"}
Cause
The model was never trained for tool calling. codellama, llama2-uncensored, base models and embedding models only advertise completion.
Fix
Pick a model marked tools: qwen2.5-coder:7b, qwen3:8b or llama3.1:8b. 3.1.5 detects this before sending, states it in the setup card, and falls back to classic edit blocks with your real files. Verify with ollama show <model>.
E10Model refuses to edit / says it can’t access filesAgent
"I can’t make changes to files" · "Please copy the file here" · a list of suggestions
Cause
An old transcript is poisoning it, plan mode is on, no folder is linked, or the model is too small to follow the setup card. A non-tool model can still edit in classic mode but cannot browse.
Fix
Start a new chat; confirm the folder chip, mode = build, and a tools model. Ask one explicit instruction: “Change X in file Y now. Use the tools.” If it still refuses, switch models. Do not spend ten turns debating.
E11Model says it can’t browse the webWeb
"I don’t have internet access" · "I can’t search the web"
Cause
The web chip is off, no results were attached this turn, the search upstream failed, or a classic model ignored the evidence block. Agent tools are independent of the chip.
Fix
Set the chip to auto, ask explicitly (“Search the web for … and cite the URLs”), and check the web table. On a tool model, agent mode should call web_search itself. If upstream is challenged, see E28.
E12Context window exceededModels
context length exceeded · too many tokens · exceeds num_ctx
Cause
The transcript plus injected folder contents plus attached files is larger than the model’s context. Long chats and large trees hit it first.
Fix
Start a new chat (the cleanest fix), detach large files, narrow the linked folder, or use the CLI’s /compact. In agent mode raise --ctx only if the model and RAM can afford it. A bigger context is not free.
E13Empty reply, crash, or out of memoryModels

Cause
The model does not fit in RAM/VRAM, the quant is too large, or Ollama’s runner crashed.
Fix
Restart Ollama. Run ollama ps to see what is loaded, then try a smaller model or a Q4 quant. Close games/browsers that hold VRAM. On 8 GB, stay at 7B. See E15.
E14Ollama 500 / malformed JSONOllama

Cause
A half-updated Ollama, a corrupted model blob, or a proxy returning an HTML error page instead of JSON.
Fix
Restart Ollama, update it, and retry a known-good model. Check the Ollama server log. If you use a proxy, confirm it passes JSON unchanged. Re-pull the model if only one model fails.
E15Very slow generation / fans at maximumModels
(no error — tokens crawl, GPU or CPU pinned)
Cause
The model is spilling from VRAM to RAM/CPU, the context is huge, or another GPU-heavy app is competing.
Fix
Use a 7B Q4, close other GPU apps, lower effort/context, and check ollama ps for CPU/GPU split. First load is always slower (weights are read from disk). If it still crawls, the machine is below the model’s comfortable size.

Open the composer’s model picker for this chat and select the intended model. Change Settings for the default of new chats. In the CLI, run /model with no argument to see the active one.

E24The agent loops or repeats the same tool callAgent

Cause

Fix

If it still loops, press Stop, narrow the request to one file or one outcome, lower effort, and use a stronger tool model. Run /compact in the CLI or start a new chat. Fix
Settings → Models → Providers & endpoint: re-enter the key, verify the base URL (often ends in /v1), save, and retry. Some keys need a project/org header or are region-scoped. Keys live in settings.json — never commit that file.
E31Provider 404 / unknown model or endpointProviders
API error 404: model not found · 404 page not found
Cause
The model id is not offered by that provider, or the base URL is missing/duplicating a path segment.
Fix
Copy the exact id from the provider’s model list. Check the base URL against its docs (for example https://api.openai.com/v1). Save, reopen the model picker, and pick the model again. For local Ollama, pull the model first.
E32Rate limit or request timeoutProviders
API error 429: rate limit exceeded · ETIMEDOUT · the model took too long
Cause
Provider quota, a long prompt, a cold model, or a network path that stalls.
Fix
Wait and retry with a shorter chat; reduce attached files/effort. On a local model, the first load after idle is slower. If the provider is rate-limiting, switch provider or model. A hung call is capped by the harness rather than spinning forever.
E33SSL / certificate error on a corporate networkProviders
self signed certificate in certificate chain · UNABLE_TO_VERIFY_LEAF_SIGNATURE
Cause
A corporate proxy replaces TLS certificates, and the app does not trust its root CA.
Fix
Install the organisation’s root CA in the OS trust store, or point NODE_EXTRA_CA_CERTS at the PEM before launching. Do not disable TLS verification. Local Ollama is unaffected.
E34The disk is full (ENOSPC)Launch
ENOSPC: no space left on device · There is not enough space on the disk
Cause
Model blobs, backups, Electron caches, or ordinary Windows temp files filled the drive.
Fix
Free space, then retry. Remove models you do not use with ollama rm <model> (re-pullable), clear %TEMP%, and prune old backups only if you accept losing undo history. Never delete ~/.codezy wholesale.

(terminal flashes and closes, or no window)
Cause
Node is not on PATH for the spawned terminal, Windows Terminal is missing, or the chat has no linked folder for a working directory.
Fix
Install Node LTS and reopen CODEZY. Link a folder to the chat. Try the bundled CLI directly: node <install>\resources\cli\codezy.mjs. A global codezy must be current; an old global install can point at stale code.

update check failed · download interrupted · GitHub 403
Cause
Offline, GitHub rate limiting, antivirus locking the exe, or no write permission to the install folder.
Fix
Download CODEZY-Setup-3.1.6.exe manually and run it over the existing install; data survives. If GitHub is blocked, use a mirror. Do not run the app elevated just to update; install per-user.

07

Short FAQ

The questions that come up before and after the first successful edit.

Does CODEZY send my code to the cloud?

Not by default. Inference goes to Ollama on 127.0.0.1, and sessions live in ~/.codezy. A cloud provider receives the prompt only when you select one. Web search sends the query; there is no telemetry endpoint.

Do I need an API key?

No for local Ollama. Cloud providers need their own key in Settings → Models. MCP servers may need credentials in their environment. Never commit settings.json or paste a key into a chat.

Why is a 13B model worse at agent mode than a 7B?

Agent mode needs tool calling, not raw size. codellama:13b advertises completion only; qwen2.5-coder:7b advertises tools. A trained 7B will beat a completion-only 13B at reading, calling and writing files.

Why does it keep suggesting changes instead of making them?

Usually plan mode, no linked folder, a non-tool model, or a transcript full of earlier refusals. See E10. Be explicit, start a fresh chat, and use a tool-capable model.

How can I tell agent mode is actually on?

Look for a folder chip and a tools badge. Ask it to list files: a working agent calls list_dir; a classic model can only describe the injected tree. Settings → Agent must show agent mode on, and the chat must have a folder.

Does it work offline?

Local chat, file tools, preview and the CLI work offline if Ollama and the model are local. Web search, cloud providers, GitHub update checks and npx MCP servers need a network.

Can it edit outside the folder I linked?

No. Every tool and the preview resolve paths inside the session roots and reject traversal. If a project needs two trees, link a common parent. Widening the root to your home directory would give the model access to everything.

How do I update without losing data?

Run the newer installer over the old one. Program files are replaced; ~/.codezy stays. Back up that folder first if the update is a major version.

What changed in 3.1.6

A terminal-shaped release: the CLI got a real home page, and the spinner became part of the story instead of a footnote.

CLI

A home page for the terminal

The CLI README is now a package page: a three-command quickstart, a terminal still, a chat-vs-agent table, the spinner explained, every command and flag, approvals, CI and privacy. It reads like the front door, not an appendix.

Spinner

nanospinner, on purpose

The agent REPL's nanospinner line names the live phase (thinking, read file …, run command …), shows elapsed seconds after two, drops frames while you type or approve, and writes to stderr. The loop is driven directly so Ctrl+C still interrupts a turn.

Surface

The banner names the build

The agent REPL header now reads CODEZY v2 · 3.1.6, and codezy --agent --preview includes a sample phase line. The design sheet shows the spinner, not just the boxes around it.

Identity

3.1.6 everywhere

Root and CLI manifests, both lockfiles, the installer filename, this manual's title, footer and changelog all report 3.1.6. 3.1.4 stays skipped; 3.1.5 becomes the previous release.

Previous release

3.1.5 is still underneath

Capability-aware agent mode, the setup card and turn pin, readable error toasts, six-category Settings, the three-column field manual and the command-specific help pages are unchanged. Full 3.1.5 notes remain in the repository README.

Scope

Surface, not harness

Prompts, tools, approvals and model routing are untouched. This release is about making the terminal easier to discover, easier to read and honest about the one dependency it uses.

Upgrade checklist

  • Quit every CODEZY window before installing.
  • Run CODEZY-Setup-3.1.6.exe; ~/.codezy and your chats survive.
  • Run codezy --version; it should print codezy 3.1.6. If it shows an older version, see E35.
  • Open codezy --agent: the header should read CODEZY v2 · 3.1.6. --preview shows the chrome and a spinner sample without loading a model.
  • Start a new chat for important work. Old refusals keep poisoning small models.
  • Link the project folder, run the five-minute smoke test, and set the web chip to auto if you expect current facts.
  • Keep ~/.codezy. The installer does not touch it; back it up before a major upgrade anyway.
